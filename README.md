This project represents an advanced end-to-end analytical solution designed for Human Resources Management. It is built on a Cloud Data Warehousing architecture that enables monitoring of critical indicators such as talent management, absenteeism, salary equity, and labor cost evolution.

## Repository Structure (Monorepo)

The project is designed using a microservices approach and separation of concerns:

* `/cloud_ingestion`: Python ETL pipeline responsible for authenticating with Google Cloud Platform (GCP) and ingesting raw data into BigQuery.
* `/powerbi_analytics`: Semantic and visualization layer in Power BI (`.pbip` format). Includes parameterized M queries to GCP and a robust analytical model with advanced DAX and Time Intelligence.

## Data Architecture

1. **Data Generation (Source System):** Raw data (`.jsonl`) is generated by an external microservice that simulates the HR transactional engine. This generator natively incorporates Slowly Changing Dimensions (SCD Type 2) logic to preserve the history of salaries, roles, and departments over time.
2. **Cloud Ingestion (Python):** Orchestrator script that reads local files and securely loads them into Google BigQuery using the official API. It implements a Truncate & Load strategy, optimal for analytical models that recalculate the entire history.
3. **Data Warehouse (GCP):** Google BigQuery acts as the centralized repository, automatically detecting the structure and data types from the ingestion of JSONL files.
4. **Semantic Layer (Power BI):** Parameterized native connection to BigQuery to hide the underlying infrastructure. The modeling is structured in a star schema optimized for workforce analytics.

## Local Deployment Instructions

To replicate this architecture in your own environment, follow these steps in order:

### 1. Cloud Environment Setup (GCP)
* **Step 1:** Create a project in Google Cloud and a BigQuery Dataset (e.g., `hr_analytics`).
* **Step 2:** Generate a Service Account and assign it the roles of **BigQuery Data Editor** and **BigQuery User**.
* **Step 3:** Download the access key in `.json` format and save it in a secure location outside this repository.

### 2. Ingestion Pipeline (Python)
* **Step 1:** Navigate to the `/cloud_ingestion` folder.
* **Step 2:** Create a `.env` file based on the provided `.env.example` file.
* **Step 3:** Configure your variables pointing to your GCP project, dataset, the absolute path of your JSON key, and the directory path where the source data is located.
* **Step 4:** Install the required dependencies by running in your terminal: `pip install -r requirements.txt`
* **Step 5:** Execute the loading pipeline by running in your terminal: `python bq_loader.py`

### 3. Analytical Model (Power BI)
* **Step 1:** Open the main `.pbip` file inside the `/powerbi_analytics` folder.
* **Step 2:** Access the Power Query Editor (Transform Data) and go to **Manage Parameters**.
* **Step 3:** Update the text variables `GCP_PROJECT_ID` and `GCP_DATASET_ID` with the exact names of your infrastructure in Google Cloud.
* **Step 4:** Apply the changes. The model will prompt you to sign in with your Google account (OAuth2) to validate read permissions.

## Security and Version Control

* **Credential Management:** Authentication to GCP services is isolated using environment variables and the service account file (`.json`), ensuring that cloud identity and billing are not exposed in the source code.
* **TMDL (Tabular Model Definition Language):** Just like in Enterprise-level projects, this repository uses the Power BI `.pbip` format to enable semantic version control over DAX and M code, eliminating dependencies and conflicts caused by opaque binaries (`.pbix`).
